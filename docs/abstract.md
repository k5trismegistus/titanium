# メモアプリ 技術相談｜構想・要件まとめ（現時点）

## 1. プロダクト構想

### コンセプト

- Markdownで書ける
- AIが自動で整理・再構成する
- 既存メモ同士の関係性から、新しいアイディアが創発されるノートアプリ

単なる保存・検索ではなく、

- 書いている最中に関連知識が現れ
- 複数ノートを混ぜて新しいアウトプットを生む
ことを目的とする。

---

## 2. 機能要件

### 2.1 ノート入力・管理

- Markdownで記述可能
- 画像・ファイルのアップロード対応
- ノートには「カテゴリ」を付与
    - 内容分類ではなくアウトプット先を表す
    - 例：
        - 広報ブログ用
        - Qiita用
        - 匿名ブログ用

---

### 2.2 構造理解・関連提示（Embedding）

### ベクトル化

- ノートは自動的に Embedding でベクトル表現を生成
- ノート単位だけでなく、章（見出し）単位でもベクトル化する

### 類似表示

- 類似度に基づき関連情報を画面に表示
    - ノート × ノートの類似
    - 章 × 章の類似（差別化ポイント）
- 編集中、カーソルがある章に関連する他ノートの「章」をサジェスト
- Scrapbox（Cosense）に近い体験だが、ページ単位に限定しない
- スマホでは関連ノートは非表示／折りたたみ前提

---

### 2.3 創発支援（Mix 機能）

- 画面上に表示された関連ノート／章を複数選択可能
- 「Mix」ボタンで新しいノート案を生成
- カテゴリを指定すると：
    - そのカテゴリの既存ノートの
        - 文体
        - 構成
        - 情報粒度
        を参考にしてアウトプット形式を変換
- 例：
    - メモ → Qiita記事
    - メモ → 広報ブログ

---

### 2.4 クイック生成（Quick Word）

- ヘッダーから単語を登録
- Geminiでその単語の解説記事を自動生成しノートとして保存
- あらかじめ登録しておき、サジェストやMix素材に活用

---

### 2.5 検索（ベクトル検索）

- クエリ文をEmbeddingして類似ノートを検索
- 類似度の高い順に最大5件まで表示

---

## 3. 非機能要件（UX）

### モバイルファースト

- スマホでも書きやすいUI
- Markdown記法を直接入力しなくても操作可能
- 画面上に編集補助ボタンを常設
    - 見出し（h1 / h2）
    - チェックボックス
    - インデント
- キーボード表示に合わせて `dvh` ベースで高さ調整

---

## 4. 技術要件・制約

### インフラ

- AWS または Firebase + Gemini API を利用

### コスト設計

- RDBは使用しない
    - RDS 等の時間課金サービスは不可
- 完全従量課金のみ
    - アイドル時にコストが発生しない
    - 個人開発・初期スケール前提

### アーキテクチャ思想

- サーバレス前提
- NoSQL / オブジェクトストレージ / ベクトル検索中心
- AI処理は必要時のみ実行

### セキュリティ
- ユーザーIDホワイトリスト制
    - 管理者が承認したIDのみ利用可能
    - 未承認ユーザーは機能制限または利用不可

---

## 5. 要約

- 書く → 構造化 → つながる → 混ざる → 新しい形で出る
という思考プロセスを支援するメモアプリ
- 技術的キーワード：
    - Markdown
    - Embedding（章単位）
    - サーバレス
- 従量課金

---
