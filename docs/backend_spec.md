# バックエンド機能一覧とUX対応表

※ プロトコル未確定（HTTP / Callable / Triggerは後決定）

---

## 1. バックエンドの役割整理

バックエンド（Cloud Functions）の役割は以下に限定する：

- Markdownから構造を生成する
- AI（Embedding / 生成）を実行する
- 計算量の大きい処理を肩代わりする
- UXの一貫性を壊さないためのガードを行う
- **ユーザー認可（管理者が承認したユーザーIDのみ許可）**

❌ 状態管理の主導
❌ UIロジック
❌ ユーザー判断の代替

---

## 2. 機能一覧（俯瞰）

```text
A. ノート保存・構造化
B. Embedding生成（非同期）
C. 類似セクションサジェスト
D. Mix生成
E. 整合性ガード（存在チェック等）
```

---

## 3. 機能別詳細とUX対応

### A. ノート保存・構造化

**機能概要**
notes.markdown 更新をトリガーに：

- Markdownをパース
- h1単位で sections を再生成
- sectionIndex を notes に同期

**主な処理**

- Markdown解析
- h1分割
- order計算
- section create / update / delete

**UX上の使用箇所**

- ノート編集画面
- Saveボタン押下時
- 自動保存発火時

**UX上の要件**

- 保存操作は常に即時完了する
- 構造化処理はユーザーを待たせない

### B. Embedding生成（非同期）

**機能概要**

- noteEmbedding：ノート保存ごとに生成
- sectionEmbedding：内容変更のあった h1 のみ生成
- embeddingPending フラグを管理

**主な処理**

- Gemini API 呼び出し
- ベクトル正規化（必要に応じて）
- Firestore更新

**UX上の使用箇所**

- 編集中の関連サジェスト
- ノート単位の類似判定
- Mix素材選定

**UX上の要件**

- Embedding未更新でも操作は可能
- 古いEmbeddingが一時的に使われても問題にならない

### C. 類似セクションサジェスト

**機能概要**
現在編集中の section を基準に類似する他 section を計算・返却

**主な処理**

- 候補セクション取得
- 同一ユーザー
- 最新N件 等
- cosine類似度計算
- Top-K抽出

**UX上の使用箇所**

- ノート編集画面のサジェスト欄
- 編集中、常時または定期的に更新

**UX上の要件**

- サジェストは提案であり強制ではない
- 理由説明は不要
- 存在しない sectionId が返っても破綻しない

### D. Mix生成

**機能概要**
選択された sections / notes を入力として新しいノート候補テキストを生成

**主な処理**

- 入力テキスト整形
- カテゴリ stylePrompt の適用
- Gemini API による生成

**UX上の使用箇所**

- Mixボタン押下時
- 新規ノート作成フロー

**UX上の要件**

- 結果は「提案」に留める
- 保存・破棄はユーザー判断
- 元ノートとの参照関係は表示しない

### E. 整合性ガード（存在チェック等）

**機能概要**
非同期処理によるズレをUX上で無害化する

**主な処理**

- sectionId 存在チェック
- 不整合時のフォールバック情報返却

**UX上の使用箇所**

- サジェスト経由でノートを開いたとき
- 古いEmbedding参照時

**UX上の要件**

- エラーにしない
- ノート全体は必ず表示できる
- 状態変化として自然に伝える

---

### F. セキュリティ / 認可

**機能概要**
ユーザーのアクセスを制御する。

**主な処理**

- ユーザーIDホワイトリストチェック
  - Firestore `allowedUsers/{userId}` を確認 (または環境変数のリスト)
  - 未承認ユーザーの場合は書き込み・AI利用をブロック

**UX上の使用箇所**

- アプリ起動時 / ログイン時
- 未承認時は「承認待ち」画面を表示
